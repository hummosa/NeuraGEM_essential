# NeuraGEM_base — Project Overview

NeuraGEM (Neural Generative Expectation Model) is a research codebase implementing a biologically-motivated context-learning algorithm. The core idea is to maintain a latent variable **Z** that is continuously optimized by gradient descent to minimize prediction error, alongside the usual weight updates. This dual-optimization loop lets the model rapidly adapt to shifting contexts without explicit task labels.

## Tasks Implemented

### 1. Contextual Switching Task (`ContextualSwitchingTaskConfig`)
Observations are scalars drawn from one of two Gaussians (mean 0.2 or 0.8, std 0.1). The context switches in blocks with no explicit label. The model must infer which context it is in from its own prediction errors and adapt Z accordingly.

### 2. Sequence Learning Task (`SeqLearnConfig`)
Implements the Beukers et al. (2024) blocked-training paradigm. Two task types, each with two transition sequences over 10 one-hot states. Tests whether contextual latents enable rapid task-switching after blocked learning.

### 3. Rotating Targets Task (`RotatingTargetsConfig`)
Implements the predictive-inference paradigm from Yu et al. (2025). Five shield colors map to target locations on a circle; all targets rotate simultaneously at unsignaled state-block boundaries. The model must predict attack positions from color cues, and ideally generalize zero-shot to novel rotation angles never seen during training. See [task_rotating_targets.md](task_rotating_targets.md).

## Training Pipeline Summary

1. **Config** is instantiated with experiment parameters.
2. **Datasets** are created via `create_datasets_and_loaders(config)`.
3. **Model** `RNN_with_latent(config)` is instantiated.
4. **`train_model()`** orchestrates phases (passive → active → test):
   - **Weight Update (WU)**: Standard BPTT on prediction loss → update RNN weights.
   - **Latent Update (LU)**: Gradient descent on Z to minimize same prediction loss.
5. **Logger** records inputs, outputs, Z, gradients, and phase markers throughout.
6. **Figures** are generated by `plot_logger_panels()` from the logger.

## Key Design Choices

### Dual Optimizer Pattern
The model maintains two separate optimizers:
- `W_optimizer` — updates all network weights (BPTT).
- `Z_optimizer` — updates only the latent variable Z per-batch.

This allows different learning rates, optimizer types, and regularization for each.

### Gradient Aggregation Across Time
Z is a sequence-level variable `(batch, seq_len, Z_dim)`, so its gradients are a `(batch, seq_len, Z_dim)` tensor. Rather than naively summing across time, `adjust_Z_grads()` applies one of several aggregation schemes (`exponential_increase`, `average`, `last`) before the optimizer step. The default steepness is `[2] * latent_chunks` (mild recency bias). See [algorithm_predictive_learning.md](algorithm_predictive_learning.md) for details.

### Multiplicative Gating (core mechanism)
Z is not concatenated with the input (additive gating is available but off by default). Instead, Z is projected through a static Bernoulli mask to produce a `(batch, hidden_size)` gate vector, which is element-wise-multiplied into the RNN hidden state before (or after) each RNN step. This allows context to modulate the RNN's dynamics rather than its inputs.

### Latent Carryover (`pass_previous_latent=True`)
Z from the previous batch is carried forward as the initial value for the next batch (detached from the computation graph). This acts as a warm-start for Z optimization and implements a form of meta-state memory.

## Data Shape Conventions

Throughout the codebase shapes follow PyTorch convention `(batch, time, feature)`:

| Tensor | Shape | Notes |
|---|---|---|
| `inputs` | `(B, seq_len, input_size)` | Raw observations |
| `Z` | `(B, seq_len, Z_dim)` | Latent variable; `nn.Parameter` |
| `hidden_state` | `(B, hidden_size)` | RNN hidden state at each step |
| `cell_state` | `(B, hidden_size)` | LSTM cell state; `None` for GRU/RNN |
| `outputs` (stacked) | `(B, seq_len, output_size)` | Model predictions |
| `loss` (unreduced) | `(B, seq_len, output_size)` | Per-element MSE |
| Z gradients | `(B, seq_len, Z_dim)` | Before aggregation |

Default experiment values: `B=1`, `seq_len=10`, `input_size=1`, `Z_dim=2`, `hidden_size=32`, `output_size=1`.

---

## Global Invariants

- **`batch_size=1`** in all standard experiments; the batch dimension exists for generality.
- **All tensors live on `config.device`** (GPU if available, else CPU).
- **Logger entries** use shape `(B, stride, dim)` per batch; they are concatenated into `(total_timesteps, dim)` at plot time.
- **Latent initialization**: Z starts at zeros each reset; exponential filter normalizes to sum-1 for learning-rate stability.
